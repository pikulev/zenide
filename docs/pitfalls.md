# Грабли

Всё здесь куплено отладкой. Большинство этих вещей не выдаёт ошибку — просто
молча не работает, поэтому и нужен отдельный документ.

## tmux

- **Обычный `display-popup` не хранит историю вывода.** `mouse on` и
  `history-limit` внешнего сервера не добавляют ему прокрутку. Поэтому
  `C-Space Space` запускает `zenide terminal`: временный tmux на отдельном
  сокете с минимальным `ide/tmux/popup.conf`. Колесо/трекпад прокручивают
  вывод; `C-Space [` открывает историю с клавиатуры, `q` возвращает к вводу.
  `exit`/`C-d` закрывают терминал, сервер и история удаляются. Внутренний
  шелл сохраняет внешний `TMUX`/`TMUX_PANE`, чтобы команды моста продолжали
  работать с проектом. История и стиль выделения берутся у внешнего сервера.
- **Старый `status-bg` перекрывает фон из `status-style`.** Он может остаться
  в работающем сервере от прежнего конфига, хотя в текущих файлах его уже нет.
  `source-file` не удаляет такие настройки. Тема сбрасывает глобальный
  `status-bg` через `set -gu status-bg`; проверять нужно отрисованный бар,
  а не только значение `show-options status-style`.
- **`display-popup` не раскрывает `#{}` в команде** (только в `-d` и `-T`).
  Пейн изнутри попапа узнаётся так: `tmux display-message -p '#{pane_id}'`.
  А вот `#()` внутри формата (`status-right`) раскрывается — на этом живёт
  `zenide status '#{session_path}'`.
- **`#()` считается только при отрисовке статуса У КЛИЕНТА.** В
  `display-message -p '#{T:status-right}'` job окажется пустым; проверять
  надо `capture-pane` вложенного клиента (`TMUX= tmux attach`).
- **После `send-keys Escape` нужна пауза** (`sleep 0.1`), иначе ESC склеится
  со следующим символом и приложение прочитает `Alt-<char>`.
- **`send-keys` рисуется в редакторе посимвольно.** Одним кадром — только
  bracketed paste: `load-buffer` + `paste-buffer -p`.
- **Голый `;` в `send-keys` — разделитель команд** даже с `-l`. Литерал
  записывается как `'\;'`.
- **`-t '=имя'` работает для ОКОН, но не как пейн-таргет.** Нужен
  `#{window_id}`; индексы брать нельзя — они плывут из-за
  `renumber-windows`.
- **В `tmux.conf` нельзя трейлинг-комментарий `;# …`**, а `\` в конце строки
  склеивает её со следующей.
- **`run-shell` — отложенный job.** Стартует после разбора всего конфига,
  поэтому видит ВСЕ бинды, в том числе определённые ниже него. На этом
  свойстве держится загрузчик модулей и генерация кириллических двойников.
- **`DELTA_PAGER='less -R'` в попапах diff/blame.** Дефолтный `less -F`
  мгновенно закрывает попап, если содержимое влезло в один экран. Ошибку в
  попапе показывать сообщением плюс `read -n1`, а не `display-message`:
  попап закроется раньше, чем сообщение успеют прочитать.

## helix

- **Нет remote-API.** Единственный канал — командная строка пейна, см.
  [architecture.md](architecture.md).
- **Нет autoread.** Диск мог поменяться в git-TUI или попапе, буфер об этом не
  узнает — отсюда хук, впрыскивающий `:reload-all` при входе в окно.
- **`:open` не перечитывает диск**, а лишь переключает на уже открытый буфер.
  Нужен `:reload` после, и строго до `:goto` — `reload` сбрасывает курсор.
- **Авто-сейв (`focus-lost`) НЕ запускает форматтер.** Prettier срабатывает
  только на ручном `:w`.
- **`%{buffer_name}` для файлов вне cwd отдаёт путь со схлопнутым домом**
  (`~/…`), а тильда в кавычках шеллом не разворачивается — разворачивать
  руками.
- **Shell-кавычки и кавычки Helix различаются.** В literal-аргументе Helix
  одинарная кавычка удваивается (`'it''s.txt'`). Bash 3.2 иначе обрабатывает
  backslash в `${var//…/…}`, поэтому это преобразование сделано через sed.
- **`%{buffer_name}` нельзя вставлять в shell-кавычки.** Имя с `$()` или
  backticks исполнится, а одинарная кавычка может закрыть строку. `ctx`
  использует quoted heredoc со случайным разделителем; `%u{a}` даёт newline
  уже после разбора командной строки редактора.
- **`select-window` текущего окна не вызывает хук перехода.** Если `open`
  оставить `@hx_skip_reload` после попапа над hx, следующий нужный reload
  будет пропущен. Флаг ставится только перед переходом в другое окно.
- **При сплитах парсинг статусбара не определяет фокус** (статуслайнов
  несколько). Экспансии helix знают сфокусированный сплит — отсюда `ctx`.

## fzf-попапы

- **fzf нужен tty, но tmux-пейн его даёт.** Запуск fzf напрямую из
  неинтерактивного процесса глохнет на `SIGTTIN` (`script` не спасает), а
  внутри пейна всё работает, и `capture-pane` читает содержимое. На этом
  стоят тесты попапов.
- **Готовность попапа — не промпт.** fzf рисует промпт сразу, а источник (fd,
  `git blame`) ещё сыпет данные: на экране `0/0` со спиннером. Ждать надо
  счётчик fzf. Исключение — live-grep: там список пуст до ввода запроса, и
  признак готовности как раз промпт.
- **Тумблеры — через state-машину**, а не инлайн-`sh` в `--bind`: экранирование
  там превращается в ад. `mktemp -d`, файл на тумблер, мелкие скрипты
  `run/hdr/toggle/setdir`, которые fzf зовёт через
  `execute-silent` + `transform-header` + `reload`.
- **Ввод scope — вложенный `fzf`, а не `read`**: у `read` нет line-editing.
  История scope своя (выбранные значения), не `fzf --history` — тот хранит
  запрос.
- **`--with-nth 4..` прячет служебные поля, но `{n}` в `--preview` и `--bind`
  берутся из ОРИГИНАЛЬНОЙ строки** (в отличие от `--nth`, который считает по
  видимой). На этом держится вся навигация blame-попапа; выбранное fzf тоже
  печатает оригиналом → `cut -f2`.
- **`fd` уважает `.gitignore` только внутри git-репозитория** — тестировать
  надо в `git init`.
- **Пустой запрос в live-grep → `exit 0`**, иначе `rg` матчит всё.
- **Превью `rga --passthru --no-heading`** — иначе скролл `+{2}` уезжает.
  Глоб `-g` ставится до `--`, путь после; в `run` нужен `set -f`.

## git и blame

- **`git log -L` считает номера строк по РЕВИЗИИ, а blame — по рабочему
  дереву.** История строки якорится на `sha` + номер в ТОМ коммите; иначе при
  несохранённых правках покажется чужая строка.
- **`git log -L` сам протаскивает строку сквозь переименования** — добавлять
  `--follow` не надо и нельзя: `fatal: --follow requires exactly one
  pathspec`.
- **delta не распознаёт blame с `--date=relative`.**
- **Подсветка склеивается с blame построчно** (`bat --style=plain
  --wrap=never`). Сравнивать надо `FILENAME`, а НЕ `NR==FNR`: без `bat` первый
  файл пуст, условие верно и для второго, и список выходит пустым.
- **`GIT_OPTIONAL_LOCKS=0` в статусе для бара.** Он крутится у каждого
  клиента раз в несколько секунд и иначе трогает `index.lock` под носом у
  git-TUI.
- **`#` в имени ветки — разметка tmux.** Экранировать в `##`.

## Прочие тулы

- **`myroutes` показывает локальный маршрут, а не весь путь до сервиса.**
  Список — `myroutes.local` (приоритет) или `myroutes.conf` в активном
  профиле: `$ZENIDE_PROFILE`, якорь `~/.config/zenide-profile`, иначе
  `profile/` клона. Формат — один хост/IP на строку, `#` начинает комментарий;
  файл не исполняется. Разово: `myroutes google.com` или
  `myroutes --config список.txt`. Имена разрешаются системным
  `dscacheutil`, каждый IPv4/IPv6 проверяется через `route -n get`;
  в выводе сначала все IPv4, затем IPv6, затем ошибки DNS без адреса.
  Ожидание каждой команды ограничено пятью секундами. DNS может обращаться
  в сеть, но проверок доступности, API и фонового опроса нет.
  `utun` означает туннель, а не доказанный выход через VPN: TUN-прокси
  может дальше выбрать прямое соединение. Fake-IP из DNS — тоже адрес для
  локальной маршрутизации, не адрес сервера. HTTP/SOCKS-прокси, PAC,
  браузерный DoH и правила отдельных приложений могут менять реальный путь.
  Код 1 означает ошибку DNS/чтения маршрута или блокирующий маршрут,
  код 2 — некорректный список/аргументы. Страна и внешний IP здесь неизвестны.
  macOS `route get` может вернуть 0 вместе с `not in table`: одного кода
  завершения недостаточно, проверяется также наличие `interface:` в ответе.
- **zsh: `alias -g ls=eza` подменяет и аргументы команд.** Так `mise ls`
  превращается в `mise eza` и пытается запустить несуществующую задачу.
  Для замены команды `ls` нужен обычный `alias ls=eza`.
- **ghostty: инлайн-комментарий `#` после значения ломает строку молча.**
- **ghostty: `window-padding-y` применяется только к новым окнам/вкладкам.**
  После перечитывания конфига проверять в новом окне. При
  `window-padding-balance = false` заданный нижний отступ сохраняется,
  а остаток высоты, не вмещающий целую строку, добавляется снизу: зазор может
  увеличиваться при смене шрифта или размера окна.
- **yazi 26.x: селект — секция `[indicator]`** (не `[mgr].hovered`); в
  `[filetype]` ключ `url`, а не `name` — ошибка роняет всю тему.
- **yazi: keymap плагина `sshfs` в блочном стиле** — не смешивать с массивами
  из README плагинов.
- **lazygit: `git.autoFetch: false` осознанно** — оставлял `.lock` на
  огромных репозиториях. Не включать.
- **git читает и XDG-конфиг, и `~/.gitconfig`.** Второй может переопределять
  значения первого, но его наличие не отключает XDG-файл целиком. Перед
  переносом настроек проверь `git config --global --list --show-origin`.
- **Monokai и ANSI-имена: в темах только hex.** ANSI-имена идут через палитру
  терминала, и `blue` там оказывается оранжевым (`#fd9353`).
- **macOS: нет `timeout`.** Таймаут в скриптах и тестах —
  `perl -e 'alarm N; exec @ARGV'`.
- **Комментарий, начинающийся словом `shellcheck`, разбирается как директива**
  и валит линт с `SC1072`. Фразу «shellcheck по всем файлам…» в комментарии не
  написать — переформулируй так, чтобы слово не было первым.
- **`brew shellenv` затеняет менеджер рантаймов.** Он препендит
  `/opt/homebrew/bin`, поэтому тул, приехавший в brew ЗАВИСИМОСТЬЮ чужой
  формулы, молча перебивает запиненную версию. Так `node` оказывался
  brew-овским, хотя пин был другой. Отсюда правило: `parts/mise.sh` сорсится
  ПОСЛЕ `parts/brew.sh`; расхождение ловит `zenide doctor`.
- **mise не читает `engines` из package.json.** Это поле про совместимость
  пакета, а не про версию для разработки; читается только
  `devEngines.runtime`. На проекте со старым `engines` версию надо назвать
  явно — `mise use node@18` в его каталоге. `.nvmrc`/`.node-version` тоже
  сначала включить: `mise settings add idiomatic_version_file_enable_tools node`.
- **mise: тул из `npm:`/`pypi:` не появляется на PATH без `mise reshim`.**
  Установился, лежит на диске, `mise ls` его показывает — а команды нет.
  Для `npm i -g` reshim делает обёртка (`node.npm_shim`), для правки конфига —
  никто.
- **mise: шимы и `activate` — разные механизмы, нужны оба.** `activate`
  работает только в интерактивном шелле, поэтому в попапах tmux и в
  `bash tests/*.sh` тул находится ТОЛЬКО через каталог шимов на PATH. Забыл
  строку с `--shims` — попап деградирует до «без подсветки», а doctor зелёный.
- **mise: доверие требуется не всегда, и это важно для ПУБЛИЧНОГО репозитория.**
  Файл из одних `[tools]` с точными версиями читается без `mise trust`.
  Добавил `[tool_config]`, `[env]`, `[tasks]` или шаблон — и у каждого, кто
  просто сделал `cd` в клон, на каждый вход поедет `mise ERROR … are not
  trusted`. Поэтому в корневом `mise.toml` только `[tools]`; строгий режим,
  если нужен, — разовым `mise install --locked`.

## После переименования путей

**Долгоживущие TUI читают конфиг ОДИН РАЗ — при старте.** Переименовал путь к
мосту (или переехал структурой) — у всех уже запущенных `yazi`, `lazygit`,
`scooter` в памяти остался СТАРЫЙ путь, и действие по Enter молча ничего не
делает: команда есть, файла нет. `tmux source-file` тут не помогает — он
перечитывает только tmux.

Лечится пересозданием окон (поднимутся по требованию с новым конфигом):

```bash
tmux list-windows -a -F '#{session_name}:#{window_index} #{window_name}' \
  | awk '$2=="yazi"||$2=="lazygit"||$2=="search"{print $1}' \
  | xargs -n1 tmux kill-window -t
```

Порядок после любой правки путей: `tmux source-file ~/.config/tmux/tmux.conf`
→ пересоздать окна инструментов → `zenide doctor`.

## Известные мелочи

- `E` отправляет `ya emit-to … reveal` работающему yazi, сохраняя вкладки и
  фоновые операции. Его id задаётся при создании окна (`--client-id`) и
  хранится в `@zenide_yazi_id`. Старое окно без id нужно один раз закрыть
  через `q` и открыть заново; автоматически оно не уничтожается.
- Для файлового менеджера, отличного от yazi, `E` переключает выбранный слот
  с сообщением, что контекстный прыжок пока не реализован.
- Контекстный прыжок `G` («встать на текущий файл») реализован только для
  `lazygit`: у каждого git-TUI свои клавиши, общего протокола нет. Для `gitui`
  и `tig` прыжок сводится к простому переключению, и попап об этом сообщает.
- Кириллические двойники не покрывают `copy-mode` — только таблицу `prefix`.
- `doctor --ui` использует PATH процесса, который его запустил. Проверка из
  интерактивного шелла не доказывает, что у уже запущенного tmux тот же PATH.
  Для сравнения запусти doctor и из попапа/пейна нужного сервера.
- **В Textual 8.2.8 не переопределять встроенные CSS-переменные через TCSS.**
  Например, собственный `$panel` может склеиться со встроенным значением и
  сломать разбор `hatch`. У палитры doctor свой префикс `$zenide-`.
