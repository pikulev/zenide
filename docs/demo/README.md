# Демо-запись

Запись живёт в разделе README «Инсайт: TUI даёт обратную связь ЛЛМ»: там она
не демо продукта, а доказательство того, что средой можно управлять
программно.

GIF пишется скриптом `record.sh`: он поднимает фикстуру, проигрывает
сценарий и конвертирует запись. Руками ничего нажимать не надо.

```bash
brew install asciinema agg
./docs/demo/record.sh
```

Рядом с `demo.gif` лежит `demo.cast`: он текстовый, диффится и позволяет
перегенерировать картинку под другую тему или кегль, не переснимая сцену.

## Сценарий

Одна связная сессия вместо нарезки по возможностям: человек разбирается в
чужом коде и правит его. Так видно и сами клавиши, и то, ради чего они.

Проходит по всему списку возможностей из README:

1. 🪟 переключиться на проект (`C-Space f`);
2. 🧭 вспомнить клавишу в шпаргалке (`C-Space ?`);
3. 🔍 открыть файл, не набирая путь (`C-Space o`);
4. 🕰 узнать, кто и зачем поставил захардкоженную скидку (`C-Space B`): попап
   встаёт на строку под курсором, сверху дифф её коммита, `C-l` — история
   именно этой строки;
5. 🔎 найти все вызовы по проекту (`C-Space /`), уточнить запрос;
6. ✏️ поправить код и посмотреть дифф ханка (`C-Space D`);
7. 🗂 файловый менеджер на каталоге текущего файла (`C-Space E`);
8. ✏️ замена по проекту (`C-Space R`);
9. ⚡️ разовая команда в попап-терминале (`C-Space Space`);
10. 🤖 правка из соседнего окна — так работает агент;
11. 📦 git-клиент (`C-Space g`), где правка уже видна.

Реплики «что делаем» идут через `display-message`: они на секунду занимают
строку статуса, читаются как закадровый комментарий и не захламляют экран.

## Как это устроено

Записи нужен pty, а у неинтерактивного процесса его нет. Поэтому работают два
tmux-сокета: внутренний держит сессию, которая попадёт в кадр, а пейн внешнего
даёт `asciinema` нужный pty и внутри него крутится клиент, прицепленный к
внутренней сессии.

Шесть вещей, без которых запись получается сломанной:

- **клавиши шлются во ВНЕШНИЙ пейн.** `send-keys` отдаёт байты программе в
  пейне, а не самому tmux, поэтому во внутреннем пейне префикс просто уходит
  в шелл и сцена не двигается вовсе;
- **ждать надо содержимое кадра, а не секунды.** `wait_screen` смотрит в
  `capture-pane`, пока не появится ожидаемое: blame сначала спрашивает у
  редактора текущую строку, потом зовёт git и bat, и на холодной ФС это
  заметно дольше, чем на прогретой;
- **точечные движения по тексту ненадёжны.** `f`, `miw` и прочее через
  `send-keys` отрабатывают через раз, поэтому правка делается выделением
  строки целиком (`x`, `c`) и набором заново;
- **`;` в `send-keys` съедается** даже с `-l`: это разделитель команд tmux.
  Без экранирования символ молча пропадает, и в кадре остаётся строка без
  точки с запятой;
- **попап закрываем с проверкой.** У blame есть вложенные виды (история
  строки по `C-l`), и первый Escape лишь возвращает в список. Без проверки все
  последующие нажатия молча уходят в фильтр попапа, а сцена дальше идёт
  вхолостую;
- **`git log` в попап-терминале поднимает пейджер,** и следующий `exit`
  улетает в `less`, а не в шелл. Берём команду без пейджера (`git status -sb`);
- **служебные каталоги держим вне корня проектов.** Профиль демо лежал внутри
  и попадал в список переключателя наравне с проектами;
- **по списку результатов поиска не навигируем.** `rga` отдаёт совпадения
  асинхронно, порядок между прогонами не фиксирован, поэтому выбор «вторым
  сверху» ехал бы от записи к записи. Вместо этого уточняем запрос до
  единственного совпадения;
- **запись закрывается детачем, а не `C-d`,** и хвост режется по времени.
  Ctrl-D долетает до приложения в пейне раньше, чем до `asciinema`, и helix
  понимает его как «страница вниз». А при закрытии клиент выходит из
  alternate screen и чистит экран, так что последним кадром оказывается
  пустота — то есть именно то, что видно на превью.

## Фикстура

Создаётся в `~/payments` и сносится после записи; если каталог уже есть и
создан не скриптом, запись откажется начинаться. Внутри два файла с одинаковым
захардкоженным числом (иначе поиску нечего показывать) и два коммита от разных
авторов (иначе blame одноцветный).

## Правки

Сценарий — функция `scene_session` в `record.sh`. После переснятия проверь
последний кадр: именно он показывается на превью в README.

```bash
ffmpeg -i docs/demo/demo.gif -vsync 0 /tmp/f%03d.png   # разложить на кадры
```

Две картинки сняты отдельно и скриптом не обновляются:

- `keys.png` — шпаргалка `C-Space ?`. В README больше не стоит (там GIF),
  лежит на случай, если понадобится снова. Снимается той же машинерией:
  поднять сессию,
  нажать `C-Space ?`, записать короткий cast, прогнать через agg и забрать
  кадр через ffmpeg. Брать нужно кадр ДО того, как в фильтр попадёт хоть
  один символ: `keys ❯ d` вместо `keys ❯` сужает список со 129 до 55 строк и
  выбрасывает из кадра как раз свои секции;
- `statusbar.png` в разделе «Статусная строка», снят руками.
