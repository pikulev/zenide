# Правка ядра

Прочитай сначала:
[docs/architecture.md](../../docs/architecture.md) — тезис, четыре операции
редактора, протокол инъекции, контракты.
[docs/pitfalls.md](../../docs/pitfalls.md) — грабли tmux, helix, fzf, git.

## Чего здесь не должно быть

- **Личных данных.** Ни путей, ни имён, ни тем. Пути — из
  `profile/projects.conf`, краска — из `profile/theme.conf`, выбор
  инструментов — из `ZENIDE_*`. Если захотелось хардкода — он едет в
  `profile/`.
- **Имён модулей.** Ни одного `if [ "$модуль" ]`. Модули регистрируют себя
  сами; ядро знает только список из `ZENIDE_MODULES` и зовёт `init.sh`.
- **Флагов на наличие тулов.** `command -v` в рантайме, деградация с
  сообщением. Флаг «у меня есть bat» протухнет в день установки bat.
- **Списка подкоманд.** Диспетчер маршрутизирует по файлам, `help` выводит
  описание из первой комментарной строки. Добавил файл — подкоманда есть.

## Окружение, которое уже есть

Диспетчер экспортирует: `ZENIDE_ROOT`, `ZENIDE_LIBEXEC`, `ZENIDE_PROFILE`,
`ZENIDE_EDITOR`, `ZENIDE_GIT_TUI`, `ZENIDE_FILES`, `ZENIDE_SEARCH`,
`ZENIDE_MODULES`. Переопределять — только через `profile/modules.conf`.

Перекрёстный вызов — через диспетчер по установленному пути:
`~/.config/zenide/bin/zenide ctx`. **Не** через PATH (в попапах tmux он не
гарантирован), **не** относительным путём (скрипты зовутся из разной глубины).

## Что сломается молча, если не соблюсти

- **`-N "группа: описание"` на каждом бинде.** Без заметки клавиша исчезает из
  `C-Space ?`: `list-keys -N` печатает только бинды с заметкой. Группа — из
  `ORDER` в `keys`.
- **`# keys: …` или `legend='…'`** первой такой строкой в скрипте попапа —
  иначе его внутренние клавиши в справке не появятся. Метку скрипт не пишет:
  `keys` выводит её из `list-keys`, ища, какая клавиша зовёт `zenide <имя>`.
  Переименовал подкоманду — метка найдётся сама, но только если бинд в
  `tmux.conf` переименован тоже.
- **Протокол `@hx_skip_reload`.** Любой НОВЫЙ впрыскиватель в helix обязан
  ставить флаг, если сам переключает окно, иначе подерётся с хуком за
  командную строку и уронит текст команды в буфер.
- **Порядок `open → reload → goto`.** `reload` сбрасывает курсор, поэтому
  `goto` всегда последний.
- **`auto-save.focus-lost` в helix.** На нём держится безопасность `reload`.
  Не выключать и не «оптимизировать» — проверяется в `doctor`.

## Устройство fzf-попапов

Тумблеры — state-машина в `mktemp -d`: файл на тумблер плюс мелкие скрипты
`run/hdr/toggle/setdir`, которые fzf зовёт через `execute-silent` +
`transform-header` + `reload`. Инлайн-`sh` в `--bind` не писать — экранирование
там превращается в ад (в `blame` по той же причине хелперы `prev/show/linehist/
static` лежат файлами в tmpdir).

В `blame`: `Enter` — `execute` (попап остаётся), единственный `accept` —
`C-o`. Поэтому «открыть в редакторе» делается ПОСЛЕ выхода из fzf, а не через
`become`: хелперы живут в tmpdir, который сносит `trap EXIT`, и `become`
гонялся бы с удалением.

## Проверка

`./tests/run.sh` обязателен после любой правки. Отдельный тест —
`./tests/run.sh open` (и `ctx`, `reload`, `config`, `zenide`, `status`,
`popups`, `lint`).

Попапы прогоняются целиком (`t-popups.sh`): fzf нельзя запустить напрямую из
неинтерактивного процесса, но внутри tmux-пейна у него есть pty. Ввод идёт
`send-keys`, экран читается `capture-pane`. Готовность попапа определяй по
счётчику fzf, а у live-grep по промпту: там список пуст до ввода запроса.
